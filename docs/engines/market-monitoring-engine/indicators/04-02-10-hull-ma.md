# Hull Moving Average (HMA) (16)

**Version:** 11.0 (2026-08-26) — see docs/CHANGELOG.md for the canonical version history.


## 1. Introduction — Trading Function
The Hull Moving Average (HMA), developed by Alan Hull, is a near-zero-lag weighted moving average designed to reduce the lag present in traditional moving averages (SMA, EMA) while maintaining exceptional smoothness. It achieves this by applying a weighted moving average (WMA) to the difference between a fast WMA and a slow WMA, then applying another WMA of sqrt(period) to the result. HMA turns faster than EMA at equivalent periods with less noise. It is used as a trend overlay on the price chart — price above HMA is bullish; below is bearish. Price crossing the HMA line generates a Crossover signal.

## 2. Mathematical Formula
```
n = period (recommended 16)
sqrt_n = round(sqrt(n))

WMA(values) = Σ(value[i] × i) / Σ(i)   where i ∈ {1, ..., len(values)}

WMA_half = WMA(prices[n - n/2 ..])
WMA_full = WMA(prices[n - n ..])
Diff = 2 × WMA_half - WMA_full
HMA = WMA(Diff[n - sqrt_n ..])
```

## 3. Normalization
HMA is a chart overlay (PriceOverlay). It is registered as `directional: true` (because it produces directional `Crossover` signals) but its `normalized` value is always 0.0 — the directional contribution is conveyed via the `state_label` (e.g. `HULL_MA_BULLISH_CROSSOVER` / `HULL_MA_BEARISH_CROSSOVER`) and consumed by event-driven TAE policies, not by the directional confluence accumulator. The `values` sub-map carries the raw HMA value.

## 4. Signals

| SignalKind | Label Pattern | Trigger Condition | Direction |
|-----------|--------------|------------------|-----------|
| Crossover | HMA_PRICE_CROSS_BULLISH / BEARISH | Price crosses the HMA line. Transition-only via prev-bar price and HMA comparison in engine. | Bullish / Bearish |
## 5. Scoring

`hull_ma` is `directional: true` in the registry but contributes 0.0 to scoring (overlay). The HMA value is exposed as a trend reference line for entries and exits.

{

  }
}
