# Z-Score (20)

**Version:** 11.0 (2026-08-26) — see docs/CHANGELOG.md for the canonical version history.

**Group:** Regime

## 1. Introduction — Trading Function
The Z-Score measures how many standard deviations the current price is from its rolling mean. It is a mean-reversion indicator: positive Z-scores indicate the price is statistically stretched above its mean (overextended, expect reversion lower); negative Z-scores indicate price is stretched below its mean (overextended, expect reversion higher). The Z-Score is directionally inverted — high positive Z = bearish, low negative Z = bullish — because the trading thesis is reversion toward the mean.

## 2. Mathematical Formula
```
mean = SMA(close, period)
σ = standard_deviation(close, period)
Z = (close - mean) / σ
```

## 3. Normalization
The normalized score in [-1, 1] is an inverted linear mapping:
```
norm = clamp(-Z / 3.0)
```
The inversion means a high positive Z-score (price far above mean) produces a negative normalized value (bearish mean-reversion expectation). Labels: `ZSCORE_OVEREXTENDED_HIGH`, `ZSCORE_OVEREXTENDED_LOW`, `ZSCORE_ABOVE_MEAN`, `ZSCORE_BELOW_MEAN`, `ZSCORE_AT_MEAN` (|Z| < 0.5).

> **Label-naming convention (v2.1).** A signal labelled `ZSCORE_OVEREXTENDED_HIGH` fires when `Z ≥ +2` (i.e. `norm ≤ -0.67`, price extremely stretched **above** the mean → bearish mean-reversion). A signal labelled `ZSCORE_OVEREXTENDED_LOW` fires when `Z ≤ -2` (i.e. `norm ≥ +0.67`, price extremely stretched **below** the mean → bullish mean-reversion). The HIGH/LOW suffix refers to the **price position** (high vs low relative to the mean), not the sign of the normalized value. The runtime normalizer in `crates/market-analyzer/src/indicators/normalized/extended.rs::normalize_zscore` uses the same `±2σ` thresholds; this document is the authoritative source of truth.

## 4. Signals

| SignalKind | Label Pattern | Trigger Condition | Direction |
|-----------|--------------|------------------|-----------|
| Threshold | ZSCORE_OVEREXTENDED_HIGH | `Z ≥ +2` ↔ `norm ≤ -0.67` (price extremely above mean → bearish mean-reversion) | Bearish (mean reversion) |
| Threshold | ZSCORE_OVEREXTENDED_LOW | `Z ≤ -2` ↔ `norm ≥ +0.67` (price extremely below mean → bullish mean-reversion) | Bullish (mean reversion) |
| ZeroLineCross | Z-Score zero cross | Z crosses 0 (reverts past the mean). Transition-only via prev-bar Z comparison in engine. | Bullish / Bearish |

> **Trigger thresholds.** Threshold units are derived from §3's `norm = clamp(-Z/3.0)`: HIGH triggers when `norm ≤ -0.67` (equivalently `Z ≥ +2`), LOW triggers when `norm ≥ +0.67` (equivalently `Z ≤ -2`). The `±0.67` bound is exactly `2/3` — the geometric value where `|Z| = 2`. Anything looser (`±0.1`) fires at trivially-stretched states (e.g. `Z = 0.4 → norm = -0.13` would falsely trigger `OVEREXTENDED_HIGH`).

> **Symmetric trigger condition (correction).** The previous version used `|Z| ≥ 2` for **both** the HIGH and LOW signals, which made them fire **simultaneously at either extreme** (e.g., Z = +2.5 would trigger both `ZSCORE_OVEREXTENDED_HIGH` and `ZSCORE_OVEREXTENDED_LOW` at once). The corrected conditions split the absolute value: HIGH requires `Z ≥ +2` (price stretched above its mean → bearish reversion), LOW requires `Z ≤ -2` (price stretched below its mean → bullish reversion). The two regimes are now mutually exclusive.
