# Historical Volatility (20)

**Version:** 11.14 (2026-10-16) — see docs/CHANGELOG.md for the canonical version history.


## 1. Introduction — Trading Function
Historical Volatility (HV) measures the standard deviation of logarithmic price returns over a lookback period, annualized. It quantifies how much price has moved (regardless of direction) and is used as a pure volatility gauge. HV is a non-directional gate — it never contributes a bullish or bearish directional score. Traders use it to assess regime context: extreme HV warns of chaotic conditions; low HV signals a potential impending expansion.

## 2. Mathematical Formula
```
log_return[i] = ln(Close[i] / Close[i-1])
HV = σ(log_returns, period) × √((86 400 / timeframe_secs) × 365)   × 100
```
Where σ is the standard deviation and `timeframe_secs` is the pipeline's candle duration.

> **Annualization base.** The platform uses `365` (crypto-native, continuous-trading market) rather than the traditional equity `252` (US trading days). This convention aligns the HV engine with the rest of the platform's analytics (which all annualize over 365 days, e.g. `01-00-introduction-to-quantitative-trading.md §4.1`). Changing the annualization base across engines introduces a ~20 % scale mismatch on the same price series.

> **Duration-aware scaling (v11.13.2).** HV is computed per-duration and each duration's
> per-bar σ must be scaled by its own annualization factor `√((86 400 / timeframe_secs) × 365)`
> — implemented once as `market_analyzer::indicators::ratio::annualization_factor` and shared
> with the Sharpe family. Previously the factor was hardcoded to `√365`, which is `√(1 day)`
> and therefore correct **only for 1d bars**; every sub-daily duration reported its raw per-bar
> σ as if it were annualized (1s was off by ~5 600×, which also made the `LOW_VOLATILITY`
> band fire permanently and the `EXTREME_VOLATILITY` signal unreachable).
>
> This is what makes a multi-timeframe volatility read comparable across columns: a market with
> ~8 bp per-minute σ reports a similar annualized figure at 1s, 1m, 1h and 1d, because each
> column's per-bar σ is scaled by its own horizon.

## 3. Normalization
HV is a non-directional gate (`directional: false`). Its normalized value is always 0.0 (never influences directional scoring), but the state label classifies volatility level:
- HV_EXTREME_VOLATILITY → triggers a Threshold(Neutral) signal
- HV_HIGH_VOLATILITY
- HV_NORMAL_VOLATILITY
- HV_LOW_VOLATILITY

Band thresholds (on the annualized percentage): `EXTREME >= 100`, `HIGH >= 60`, `LOW <= 20`, else `NORMAL`.

## 4. Signals
| SignalKind | Label Pattern | Trigger Condition | Direction |
|-----------|--------------|------------------|-----------|
| Threshold | EXTREME_VOLATILITY | HV at extreme levels (regime outlier warning) | Neutral |

## 5. Configuration
```json
{
  "indicators": {
    "hv_period": 20
  }
}
```

The duration is **not** configured here — it is supplied by the pipeline this indicator runs on
(`HistoricalVolatility::new(period, timeframe_secs)`), so every value in `[workspace].timeframes`
is scaled correctly without operator action.
