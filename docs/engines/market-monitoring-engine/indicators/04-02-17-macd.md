# MACD Momentum Trading Strategy (12, 26, 9)

**Version:** 11.0 (2026-08-26) — see docs/CHANGELOG.md for the canonical version history.


## Structural Mechanics

The MACD indicator consists of three components derived from price data:

1. **MACD Line** = 12-period Fast EMA − 26-period Slow EMA
   - When the fast EMA is above the slow EMA, the MACD line is **positive** (bullish momentum)
   - When the fast EMA is below the slow EMA, the MACD line is **negative** (bearish momentum)

2. **Signal Line** = 9-period EMA of the MACD Line
   - Smoothed version of the MACD line used to identify crossovers

3. **Histogram** = MACD Line − Signal Line
   - Represents the **mathematical distance** between the MACD line and its signal
   - Zero when the two lines cross
   - Positive when MACD line is above signal (bullish momentum accelerating)
   - Negative when MACD line is below signal (bearish momentum accelerating)

---

## The Momentum Gap Formula

The histogram is a visual and numerical proxy for **momentum acceleration and deceleration**:

- **As the gap between the 12 and 26 EMAs expands**, the MACD line moves further from zero, and the histogram bars **grow taller** — momentum is accelerating.
- **As the gap between the 12 and 26 EMAs converges**, the MACD line approaches zero, and the histogram bars **shrink** — momentum is decelerating.

This principle means you do not need to wait for an opposite crossover to exit a trade. Histogram contraction alone signals that the trend's energy is exhausting.

## The Zero-Line Filtering Rule

The position of the MACD line relative to the **zero-line** determines whether a crossover is actionable:

### Bullish Crossovers (MACD line crosses above Signal line)

- **Favorable**: Only when the MACD line is **below zero** (negative territory). A crossover deep below zero (e.g., -500 to -1000 points for BTC-scale assets) signals a deeply oversold market preparing for a mean-reverting bounce.
- **Unfavorable (Reject)**: A bullish crossover above zero (positive territory). This represents momentum continuation, not a fresh reversal — late entries carry poor risk/reward.

### Bearish Crossovers (MACD line crosses below Signal line)

- **Favorable**: Only when the MACD line is **above zero** (positive territory). This signals stretched upward momentum preparing for distribution.
- **Unfavorable (Reject)**: A bearish crossover below zero. This represents momentum continuation downward, not a fresh reversal.

### False Bullish Crossover Warning (Extreme High Rejection)

The "extreme high" reference in earlier versions of this document is a **secondary sanity-check**, not a separate filter. The Zero-Line Filtering Rule (`§3`) already rejects *any* bullish crossover with `macd_line ≥ 0` regardless of magnitude — so the additional "+1000" threshold is logically redundant (a bullish crossover with `macd_line = +50` is rejected by the same rule that rejects `+1000`). The institutional canonical form is: **the Zero-Line Filter is the sole MACD crossover filter; no separate extreme-value filter is required**.

The motivation remains accurate:

- Late-stage retail FOMO entries are always rejected (they occur above zero).
- Whale liquidation cascades creating temporary price spikes are likewise caught.
- A crossover caused by the signal line dropping as fast EMA momentum decays — also above zero — is correctly rejected.

**Scale rule** (kept for documentation, not as a filter): thresholds scale with asset price. For a $100 asset, ±10–30 may indicate "extreme" scale; for BTC at $30,000, ±500–1000. These are reference values for visualization, *not* filter triggers.

## Early Exit: Histogram Contraction Protocol

A trade does NOT need an opposite crossover to exit. Momentum exhaustion is visible in the histogram directly:

**Formula**:
```
If: current_histogram < histogram_peak × (1 − contraction_threshold)
Then: Exit the trade immediately
```

**Default contraction threshold**: 0.30 (30%)

**Example**:
- Histogram peak during the trade = +0.45
- Contraction threshold = 30% → exit trigger = 0.45 × 0.70 = 0.315
- Next bar prints 0.28 → histogram has contracted 37.8% from peak → **EXIT**

This exit fires well before a MACD line/signal crossover would occur, capturing profits before full momentum decay.

## Confluence Checklist

Before entering a trade based on a MACD crossover, verify at least 2 of the following:

1. **RSI Confluence**
   - For bullish entry: RSI is exiting oversold territory (RSI crossing above 30) OR a **Confirmed Bullish RSI Divergence** is active
   - For bearish entry: RSI is exiting overbought territory (RSI crossing below 70) OR a **Confirmed Bearish RSI Divergence** is active

2. **Price breaking S/R levels**
   - For bullish entry: price has broken above or is holding the nearest Support level (S₁ or S₂)
   - For bearish entry: price has broken below or is reacting off the nearest Resistance level (R₁ or R₂)

3. **Macro Trend Alignment**
   - For bullish entry: price is trading above the 200 EMA on the Macro timeframe
   - For bearish entry: price is trading below the 200 EMA on the Macro timeframe

> Registry manifest (`signal_types`): Crossover, ZeroLineCross, Divergence, TrendFlip. The table mirrors the registry; the TrendFlip row is declared capability that the deriver has not yet wired.

The Crossover signal fires via two distinct paths: (1) a structured push in `normalize_all` when `inputs.macd_crossover` is Some, and (2) a label-based trigger in `derive_signals` matching "CROSSOVER". Duplicate badges from both sources are intentional — each represents a separate detection layer. **However, the Zero-Line Filter Rule suppresses signal emission for crossovers above/below zero (FOMO_REJECTED / PANIC_REJECTED); the `state_label` is set to `MACD_REJECTED_CROSSOVER` and no `IndicatorSignal` is emitted for the rejected bar.** This prevents event-driven TAE policies from acting on a filtered event.

## Normalization

The MACD normalized score in [-1, 1] is computed from crossover state and histogram dynamics:

**Crossover present:**
- Bullish crossover, macd_line < 0: norm = 0.8 + 0.2 × tanh(|macd_line|) → [0.8, 1.0) (ACCELERATING)
- **Bullish crossover, macd_line ≥ 0: norm = 0.0 (FOMO_REJECTED — the Zero-Line Filtering Rule rejects this crossover; it adds zero to the directional confluence)**
- Bearish crossover, macd_line > 0: norm = -(0.8 + 0.2 × tanh(|macd_line|)) → (-1.0, -0.8] (ACCELERATING)
- **Bearish crossover, macd_line ≤ 0: norm = 0.0 (PANIC_REJECTED — the Zero-Line Filtering Rule rejects this crossover; it adds zero to the directional confluence)**

**No crossover:** determined by histogram expansion vs contraction (peak vs current). The continuity invariant (`[continuous ramp, no step jumps]`) is preserved by linearly interpolating between the "fully expanding" and "fully contracting" extremes rather than dropping to a flat value:

- `|histogram| ≈ 0`: `0.0` (`MOMENTUM_FLATLINE`).
- Let `r = clamp(|histogram| / histogram_peak, 0, 1)` and `s = tanh(|histogram|) ∈ [0, 1)`. The peak-relative contraction ratio is `c = 1 − r`. Then:
  - `macd_line > signal` (bullish regime): `norm = (0.4 + 0.3 × s) × r + 0.1 × (1 − r)` ∈ `[0.1, 0.7]`. Continuous in both `r` and `s`; equals the expanding extreme `0.4 + 0.3s` when `r = 1` and falls smoothly to `0.1` as `r → 0`. Label: `BULLISH_MOMENTUM_EXPANDING` (r > 0.5) or `BULLISH_MOMENTUM_EXHAUSTION_WARNING` (r ≤ 0.5).
  - `macd_line < signal` (bearish regime): `norm = −[(0.4 + 0.3 × s) × r + 0.1 × (1 − r)]` ∈ `[−0.7, −0.1]`. Mirror image. Label: `BEARISH_MOMENTUM_EXPANDING` or `BEARISH_MOMENTUM_EXHAUSTION_WARNING`.

> **Continuity.** The "no crossover" branch uses a continuous piecewise formulation rather than discrete flat values (`±0.3` for contracting, regardless of histogram magnitude). Discrete values would produce step jumps in the per-tick confluence sum as the histogram drifts across the `histogram_peak × (1 − 0.30) = 0.30 × peak` threshold. The continuous form preserves the ADX-style continuity invariant: the per-tick confluence derivative is bounded and there is no discontinuity at the contraction boundary. State labels remain exhaustive; only the underlying value mapping becomes continuous.

> **Reject semantics.** The previous version assigned `±0.2` to `FOMO_REJECTED` / `PANIC_REJECTED` — this contradicted the Zero-Line Filtering Rule (§3) which states that these crossovers are *unfavorable* and *rejected*. A "rejected" crossover must contribute **zero** to the directional confluence, not a residual vote. Implementations must read the normalized value as 0.0 for these cases; any non-zero value would let a filter-out signal leak into the directional accumulator.

Confirmed divergence hard-overrides to ±1.0. The `values` sub-map carries: `line`, `signal`, `histogram`, `histogram_peak`.
